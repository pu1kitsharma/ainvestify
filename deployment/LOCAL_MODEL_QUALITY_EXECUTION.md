# Local-model investment package execution plan

Status: implementation plan, not an accepted model or release. Scope is any
startup matching the user's investment brief worldwide; India pre-seed/seed is
a pilot evaluation slice. No company names, answers or source passages are
embedded in product logic. The local model authors discovery judgments,
recommendations, analysis and narrative. Software records sources and responses,
computes financial formulas, checks exact bindings, renders files and blocks
unsupported output. Human and independent model review evaluate outputs; they
do not write replacement company answers.

## Failure to fix

The room currently attempts a large two-part memo and review under a short
bounded inference budget. Saved attempts show repeated part corrections and no
accepted private memo. Source selection stops at a fixed context bound, so a
long evidence set can be underrepresented. A prior review could influence a
different reconstructed memo. Local PDF fixtures prove file structure only;
they do not prove decision quality or full investor-package consistency.
In a separate six-company public-only local comparator run, the model first
omitted a required decision and later inferred current fundraising from a
historical round. Both raw outputs were retained; the latter passed older
mechanical gates but failed content inspection. This is an evaluation finding,
not a company-specific product rule or a qualified discovery route.
Two independent Claude Code evaluators subsequently confirmed the rejection
and identified further source-level contradictions: cross-company location,
reversed event chronology, duplicated and conflicting funding records,
round labels or amounts applied to the wrong event, and unequal treatment of
missing fields. The saved output is unsuitable for promotion. Generic lexical
checks catch some obvious claims but cannot establish semantic correctness.

## Execution order

### Immediate repair sequence — 2 October 2026

This sequence governs the next production changes before another PDF trial:

1. Fail closed when bounded source selection omits passages. Retain the full
   eligible inventory and omitted IDs; draft only after a local-model
   selection pass has inspected conflicting and decision-relevant evidence.
   An incomplete bundle cannot receive a passing review of the whole case.
2. Freeze the exact local draft, field, correction and reviewer model profiles
   with the source/version digest and as-of date. Resume by recorded task ID
   and input digest; never repeat a completed correction or reuse a review of
   changed prose.
3. Replace the remaining multi-claim review-revision patch with bounded
   single-claim/field tasks. Route each reviewer defect to its actual cited
   claim; preserve other claims. Save every raw response and reject unsupported
   numbers, dates, status upgrades or source changes. The reviewer must inspect
   the exact reconstructed memo and complete retained source set.
4. Run public-only local qualification across sparse, conflicting and changed
   source cases. Measure unsupported-claim false acceptance, abstention,
   reviewer error, latency and source omission. A reviewer disagreement or
   105-second timeout blocks acceptance; it does not authorize a PDF.
5. Once a memo passes, render a clearly marked private draft PDF from that
   exact reviewed revision and inspect its citations, readable pages and
   consistency against the DOCX. Complete financial calculations and all
   required exported formats/checks before any investor-ready release.

Claude Code's authorized role in this sequence is independent plan/code/public
output evaluation. It may propose generic fixes and tests, but it must not
author company conclusions or receive private room data. The local LLM remains
the only product response author. Claude findings require code and local-run
verification before acceptance.

**Independent review, 2 October:** An authenticated Claude Code agent team
reviewed a sanitized snapshot of this plan and 17 selected code/test files.
Three read-only teammates examined evidence provenance, memo replay/model
identity, and release validation, then challenged each other's findings. They
converged on the batch review-revision path as the main likely cause of current
memo non-acceptance; missing source selection blocks richer cases; unfrozen
draft/reviewer roles and numeric source-title credit were silent integrity
risks; and the draft `research_brief` kind broke release-manifest validation.
This was static review, not product inference or live acceptance. Follow-up
code blocks unadjudicated passages, retains the private full inventory and
opaque IDs, prioritizes the rights-bound indexed record, freezes each new memo
model role, checks saved response roles, narrows numeric title credit to the
exact prose span, and excludes the internal research preview from the investor
release manifest. The reviewer-revision path now uses isolated, model-authored
field corrections with exact replay and a fresh review. Long inventories use
bounded local-model passage dispositions; changed or incomplete inventories
block. These are implemented and tested in isolation, not qualified by a live
local-model run. The current selector cannot prove that a model-excluded
passage was immaterial, so any exclusion leaves the memo awaiting independent
source review. An all-included set above 30 passages or 24,000 characters
also stops before drafting. Up to six selection batches can consume all three
room passes before memo drafting. Long-inventory acceptance remains open. The
preview PDF remains a preview; it must not be
relabeled as the required IM PDF until its exported bytes match the validated
DOCX revision and pass layout and content inspection.

**3 October public-only trial:** The installed local Ollama service was
available. A fresh ignored trial directory copied only the previously retained,
rights-cleared four-passage StartupDB evidence for 1001 AI. Three 90-second
passes saved both draft parts, model-authored corrections and isolated-field
responses. The final pass failed evidence validation before any review: the
model added a number to its risks sentence that was absent from its cited
claim. Raw responses remain under
`runtime_qualification/public_memo_repair_2026-10-03/`; no accepted memo,
recommendation or PDF resulted. The failure exposed a retry defect: a
schema-valid but source-invalid isolated response was replayed as terminal on
resume. Code now retains that response and permits at most three exact,
model-authored corrections with validator feedback within existing pass
budgets; this repair has offline tests but has not been retried live. A second
read-only Claude Code agent-team review confirmed that a selected-only reviewer
could miss excluded adverse evidence; the exclusion safety stop closes that
false-acceptance route, while independent exclusion review remains open. It
also identified an unsupported artifact-kind admission path; draft
registration now validates release kinds/formats and the explicit research
preview kind. These code checks do not establish investment quality.

1. **Freeze and record every dependency.** Persist the as-of date, source
   version IDs, input revision, local model IDs, raw responses, patches and
   review-to-memo digest. Resume only against matching inputs. Never silently
   reuse a review after memo text or evidence changes. The date and exact-review
   fixes are implemented in the local memo path, including renderer-side
   verification that the reviewer saw the exact memo and source set; live
   resumption is pending. The worker now advances through multiple saved memo
   stages in one bounded pass when call/time budget remains, leaving passes
   available for model-authored correction and fresh review.
2. **Build evidence coverage before drafting.** Inventory all eligible public
   and private passages with classification, rights, publisher, date and
   version. In bounded batches, have the local model select decision-relevant
   passages and explain omissions; retain its raw selection. Require coverage
   of identity, stage, product, traction, finance, competition, risks and
   contradictory evidence where available. An unsupported field remains
   explicitly missing. No room-private bytes enter shared KB or public queries.
   The current binder now records available/selected/omitted passage counts;
   the model-authored selection stage remains to be built.
3. **Make the recommendation a small independent model task.** The local model
   chooses exact source excerpts and authors a decision and reasons. A separate
   local reviewer evaluates the complete retained evidence, including conflicts
   and the frozen date. Exact quote/number checks and reviewer rejection block
   promotion. Connect the existing fieldwise prototype to the production room
   only after its provenance and resume contract are implemented; do not
   transplant a manually written recommendation.
4. **Draft sections from the accepted evidence bundle.** Generate bounded
   sections with explicit reported/verified/inferred/missing status. Each
   section has source-version bindings and its own model response ID. Recompute
   affected sections when inputs change. A fresh independent review assesses
   the exact reconstructed memo; corrections remain model-authored and bounded.
5. **Financial work and files.** Accept consumer projections as source inputs,
   inventory formulas and hidden cells, resolve assumptions and period/entity
   scope, and calculate scenarios with a qualified deterministic engine. The
   local model explains results and uncertainty; it cannot turn missing data
   into validated forecasts. Render memo, deck, PDFs and XLSX from one material
   revision. Validate the exported bytes, formulas, charts, cross-file numbers,
   citations, confidentiality and page layout. Mandatory failures block release.
6. **Evaluate on diverse cases after the workflow exists.** Use rights-cleared
   companies and private synthetic fixtures spanning sparse/rich evidence,
   conflicting reports, later funding, missing financials, long sources and
   changed revisions. Score citation resolution, material factual errors,
   abstention, recommendation consistency, completeness, latency and false
   acceptance. Keep development cases separate from untouched acceptance
   cases. Require qualified reviewers for financial/compliance acceptance.

## Independent evaluator role

Claude Code, if locally authenticated, may inspect source code and sanitized or
public-only evaluations and propose defects. It must not receive private room
documents, raw private responses or credentials through a hosted route. Its
suggestions are hypotheses to verify against code and local evidence, not
product responses or automatic approvals. On 2 October, the user completed
Claude Code sign-in and two read-only evaluator agents reviewed a sanitized
code snapshot. Their confirmed quote-repair and budget-alignment findings
were fixed; source-publisher independence and complete evidence selection
remain open. No private room content was included.
Two additional read-only agents reviewed the rights-cleared public comparator
case and found the contradictions recorded above. They did not generate a
replacement company answer.

## Exit criteria

No stage is complete from unit tests alone. Progress requires a live local-model
run on a real, rights-cleared company, independently checked source-bound
reasoning, a useful exported package, and all mandatory file/financial/privacy
checks on exact versions. A documented abstention is preferable to an invented
recommendation. Cloud compute can address measured capacity, never waive these
quality gates.
