# ainvestify

An AI-driven, multi-agent system for sourcing and preparing companies across sectors, then helping them raise institutional funding — the way a boutique investment bank packages a raise, not a fund screening deals for its own book.

**Lifecycle:** source candidate companies → a human reviews and promotes a lead into an actual deal → sign an engagement mandate → ingest the company's own documents → extract structured metrics with mandatory citations → human review → external research corroboration → compile a cited, reviewable document suite (Teaser / CIM / Pro-forma) → track investor interest (demand book).

This system supports that process with cited data and a reviewable memo — it does not itself contact investors, negotiate terms, or run the raise. That stays a human-led relationship/advisory activity.

## Status

**Automatic web sourcing pilot:** Enter a selection brief and optional geography on the Leads page, or ask the dashboard to find companies. No URLs are required. The local model plans search queries, public search discovers pages, and the collector researches original company/portfolio pages and observed links. Profiles retain cited passages, missing evidence, and proposed incubation next steps. Any sector/region is supported; India is the initial UI default.

Run `python3 scripts/serve_local.py` and, from `frontend/`, `npm run dev`. Local task routing uses `SOURCING_MODEL` (`phi4-mini`) for short extraction and `REASONING_MODEL` (`qwen3:8b`) with thinking enabled for analytical work, screening, retries and review. On machines with at least 24 GB RAM, Qwen3:14b handles high-complexity inputs, retries and review by default. Smaller machines use Qwen3:8b for those stages with bounded context/output budgets; explicit model overrides remain available. Models must already be installed in Ollama. `PREPARATION_MODEL` selects the fast preparation route; `REVIEW_MODEL` and `ESCALATION_MODEL` can select other supported thinking models. No paid API, automatic download, cloud inference or silent downgrade is enabled. See [routing configuration and evaluation](evals/investment_preparation/model-routing.md). The Discover page defaults to worldwide and has one brief/geography search, search-scoped results, a shortlist and history. Public Antler, SOSV and Seedcamp cards supplement YC and regional sources; dynamic searches also seek industry associations and university spinouts. Inference scheduling is FIFO per model call, so web fetching never holds the GPU queue for an entire search. URLs remain optional. Restart the API after backend edits; the stable launcher avoids reloads interrupting background jobs.

Preparation now uses stage-specific practitioner methods and original teaching examples, then critiques and revises the drafts. Unresolved model review questions remain visible on internal drafts while other documents continue. This is inference-time teaching, not trained model weights or verified fundraising execution. See the [practitioner sources, response evaluations and training-data limits](evals/investment_preparation/README.md).

Discovery uses bounded DuckDuckGo HTML search with an independent Mwmbl public API fallback. Search access and index coverage are best-effort. Challenges stop that provider. If neither yields pages, a geography-matched operator catalog is used with an explicit limited-coverage warning; unsupported regions get a retryable incomplete result. Search snippets never count as company evidence. A reserved enrichment budget researches named companies, follows observed company links, and merges facts only with identity linkage. Public PDFs are collected automatically (up to 3 MB / 10 pages of selectable text); scanned, script-rendered and login-protected sources can remain inaccessible. Evidence support is not commercial verification; assessments are proposals, not calibrated investment rankings.

API: `POST /api/leads/web-runs` with `thesis` and optional `geography` (`seed_urls` is optional); poll `GET /api/leads/web-runs/{id}`; stop with `POST /api/leads/web-runs/{id}/cancel`. Search queries, discovered URLs, phases, source outcomes and coverage warnings persist. One research job per API process; use one API worker. Restarted jobs are marked interrupted; durable resumption remains future work.

Offline verification: `python3 -m pytest tests/test_web_sourcing.py tests/test_web_discovery.py -q`. Live check without URLs: `python3 scripts/smoke_web_sourcing.py --brief "Agricultural companies making solar dryers" --geography India --max-pages 2`. Uses a temporary database and local model. `--discover-only` checks discovery separately.

**AI research:** Natural company requests are interpreted into sector, geography and evidence criteria before retrieval. The local model screens candidates, selects observed research links and assesses collected evidence. Discover shows the research brief, criterion verdicts and short AI decisions separately from source coverage. “Rapidly growing” requires dated operating comparisons; funding or portfolio membership alone remains insufficient. Public sources and local models can fail, and unresolved criteria stay unverified.

**Company operations:** Open a shortlisted company to **Research → Pitch founders → Get investment ready**. Research and founder email generation use the local model. Investment preparation has its own job: AI assesses engagement suitability, then produces a screening memo for unresolved fit or a decision memo, commercial validation document and investor narrative for supported preparation. Each work product includes sources and specific company inputs needed to develop it. An evidenced mismatch stops the incubation path. These are preparation drafts, not proof of investment readiness or executed fundraising. The dashboard links companies to this work; standalone document records remain accessible separately.

**Company updates:** Paste a named founder/finance update under Business performance. `POST /api/operations/workspaces/{id}/metric-imports` queues AI source-block selection, checks the quoted month/currency/metric definitions, saves supported company-reported figures, calculates operating metrics and regenerates the company brief. Original updates, source references, corrections and exceptions are retained. This supports explicit historical monthly text, not arbitrary accounting integrations or audited financial verification. Manual figure entry is a secondary fallback. No messages are sent; experiments, investor outreach and closing execution remain incomplete.

The source registry includes Dataful company records and aggregate startup counts as **metadata-only** until a permitted download entitlement is configured. No paywall is bypassed and the public preview is never treated as the full register. A free CC0 Wikidata connector supplies company identities, website pointers and row-level provenance before web enrichment. Its India hotel-company query has been live-tested; coverage of other sectors/regions is limited and explicit. Aggregate datasets cannot be used as company financial evidence.

API: `GET /api/operations/datasets`, `GET /api/operations/workspaces`, `POST /api/operations/leads/{id}/evaluate`, `POST /api/operations/leads/{id}/prepare`, and version-checked `POST /api/operations/workspaces/{id}/attestations`. The controls are evidence/authority review requirements, not a legal compliance certificate. See architecture §16.16 for source rights and dated India regulatory references. Live local-model check: `python3 scripts/smoke_operations.py` (temporary database).

For linked operating workspaces, teaser safe-to-send confirmation enforces release checks and upstream dependencies. Approval is bound to the supporting evidence version; changed evidence removes current approval status from document views while preserving the historical review.

**Search relevance and result isolation:** Startup briefs first read public startup-directory cards, filtered by the actual brief, then continue web discovery and enrichment. Directory content is fetched live; no company names are seeded into the search implementation. The YC adapter prefers recent batches for startup requests and excludes reported public/acquired/inactive entries. It is a limited, source-biased corpus, not representative market coverage. The original search words are preserved; archive pages and obvious geography conflicts are filtered before reading. `GET /api/leads/web-runs/{id}/leads` returns that run's saved evidence snapshots. Earlier companies do not appear under a new or empty search. Browser regression: `node scripts/check_discovery_ui.cjs` with Playwright installed (or `DISCOVERY_PLAYWRIGHT_MODULE` pointing to its module).

**Phase 0** — local, CPU-only validation, zero cloud spend. See `CLAUDE.md` and `deal_automation_architecture.md` for full project context, architecture, and the current list of open gaps.

## Setup

1. Install [Ollama](https://ollama.com/download) and confirm `ollama serve` is running.
2. `pip install -r requirements.txt` (or see the imports across `agents/*.py`, `schemas.py`, `store.py`, `main.py` for the current dependency set).
3. `python3 main.py "<what you want to do>"` — e.g. `"find promising fintech companies to incubate"` or `"screen this deal, I have the pitch deck ready"`.

Startup discovery now reads YC and Blume public portfolios, with Villgro included for India. Candidate slots are reserved across publishers; empty/blocked sources can cause an explicitly limited backfill. Cards name their discovery source. Source coverage groups directories, search engines, datasets and research pages, with selected-company counts, cited claims and failures; search links are never counted as company evidence. Dataset access and licensing details live within search coverage.

Legacy four-stage preparation API: `POST /api/operations/leads/{id}/prepare-jobs`, then poll `GET /api/operations/workspaces`. Generation queues for the shared local-model slot and reuses current draft packs. Each stage is saved against its evidence version; retry skips current stages. Restarted jobs are interrupted; background jobs are not automatically resumed. Browser checks: run `scripts/check_discovery_ui.cjs` and `scripts/check_operations_ui.cjs` with `DISCOVERY_PLAYWRIGHT_MODULE` set to an installed Playwright module path. They mock API responses and do not modify saved companies.

AI plans now contain a concrete task, deliverable, required inputs and proposed success measure for each stage, with a citation to the company’s business evidence. Generic action-only packs require an update. Company stage labels distinguish collected evidence and prepared questions from execution and release checks.
